Toast

Stacked notifications: typed, promise-based, hover and focus to expand and pause, F6 to reach them, swipe to dismiss, anchored to an element. The feedback kit's toaster (undo, positions, an inbox) builds on the same store.

Source: @kitora/ui (the primitive the kits compose)

01Basic

A provider, a viewport and a button that adds a toast with a title, a description and an action; it closes itself after five seconds, and F6 moves keyboard focus into the stack.

02Types and promise

A toast type styles the toast and picks its icon; loading never closes itself. priority: "high" announces urgently. promise follows a promise from loading to success or error.

03Stacked

Older toasts peek out behind the newest and fade past the limit; hovering or focusing the stack lays them out in a column and stops every timer.

04Swipe to dismiss

swipeDirection chooses the directions a toast can be swiped away in; the swipe writes data-swiping, data-swipe-direction and --toast-swipe-movement-x and -y.

It stays until you dismiss it. Past 40 px the toast leaves the way you pulled it; let go sooner and it springs back.

05Anchored toast

A toast added with positionerProps.anchor sits next to that element, with an arrow, instead of in the viewport. It does not stack or swipe.

06Priority, rich and custom toasts

Errors and priority: "high" toasts are announced at once; titles take JSX and toast.custom draws one toast with your own markup.

07Deploy card

A Card, a Badge and a Button: the deploy button follows a promise through a loading toast to a success toast whose action rolls the badge back.

ProductionIdle
Ship the latest build to every region.

08Feedback kit toaster

The feedback kit's toast() on its app-wide Toaster: the same store, with positions, undo and an inbox on top.

09Build your own

Toasts from the primitives' Toast parts and useToastManager; a rebuild test compares them with ui's (raising, stacking, F6 into the region, actions, Escape).

Anatomy

Which part renders inside which in the examples above, from @kitora/ui/toast: each part's data-slot, the @kitora/primitives part it renders, its role, the state attributes it writes and the CSS variables it sets (style them with data-open:, data-checked: and the rest). Build your own builds the same thing from the parts alone.

Props

Toast

One toast. The stack is CSS over the variables the root writes: older toasts peek out behind the newest, smaller and fading (--toast-index); hovering or focusing the viewport lays them out in a column (data-expanded, --toast-offset-y); a toast enters from below, leaves downward or the way it was swiped (--toast-swipe-movement-x and -y), and one pushed out by the limit fades (data-limited).

  • toastrequiredToastObject

    The toast to render.

  • swipeDirectionSwipeDirection | SwipeDirection[]

    Default ["down", "right"]

    Direction(s) in which the toast can be swiped to dismiss. A toast with an anchor does not swipe.

  • swipeThresholdnumber | ((element: HTMLElement, direction: SwipeDirection) => number

    Default 40

    Distance (px) past which a released swipe dismisses; a function gets the element and the direction. A Kitora seam: Base UI's is fixed at 40.

Plus render, and className / style as functions of the part's state, and every <div> prop.

AnchoredToast

An anchored toast: a small card that points at its anchor. Use inside ToastPositioner.

  • toastrequiredToastObject

    The toast to render.

  • swipeDirectionSwipeDirection | SwipeDirection[]

    Default ["down", "right"]

    Direction(s) in which the toast can be swiped to dismiss. A toast with an anchor does not swipe.

  • swipeThresholdnumber | ((element: HTMLElement, direction: SwipeDirection) => number

    Default 40

    Distance (px) past which a released swipe dismisses; a function gets the element and the direction. A Kitora seam: Base UI's is fixed at 40.

Plus render, and className / style as functions of the part's state, and every <div> prop.

ToastAction

The toast's action button (its label and handler are the toast's actionProps).

  • nativeButtonboolean

    Default true

    Whether the part renders a native <button>; set false when render gives another element.

Plus render, and className / style as functions of the part's state, and every <button> prop.

ToastArrow

An arrow on an anchored toast pointing at its anchor; put it in AnchoredToast.

Plus render, and className / style as functions of the part's state, and every <div> prop.

ToastClose

The × button: out of the way until the stack is hovered or the button has focus.

  • nativeButtonboolean

    Default true

    Whether the part renders a native <button>; set false when render gives another element.

Plus render, and className / style as functions of the part's state, and every <button> prop.

ToastContent

The padded, measured box inside a toast; the toasts behind the newest hide their content until the stack opens.

Plus render, and className / style as functions of the part's state, and every <div> prop.

ToastDescription

The toast's message in smaller muted text, under the title; it shows the toast's description.

Plus render, and className / style as functions of the part's state, and every <p> prop.

ToastIcon

The icon of a toast type (success, info, warning, error, loading); nothing for any other type.

  • typerequiredstring | undefined

    The toast's type; only the five named above draw an icon.

  • classNamestring

    Classes added to the icon.

ToastPortal

Moves an anchored toast into the page's body (or container).

  • childrenReact.ReactNode

    The positioner and toast to move.

  • containerPortalContainerOption

    Render into this element instead of document.body.

  • anchorElement | null

    The element the toast points at, when the portal is not given a Positioner toast={toast} as a child to read it from: the toast goes into the scope (PortalHost) that contains it, not the one the manager component happens to be rendered in.

  • classNamestring

    A class for the node the portal creates.

Plus every HTML prop.

ToastPositioner

Places an anchored toast against its positionerProps.anchor; it sits above the anchor by default.

  • anchorElement | null

    An element to position the toast against. Defaults to the toast's positionerProps.anchor.

  • toastrequiredToastObject

    The toast object associated with the positioner.

  • stickyboolean

    Default false

    Keep the popup against its anchor's edge while the anchor scrolls away.

  • sideAnchoredSideRequest

    Default "top"

    Which side of the anchor the popup sits on; inline-start / inline-end follow the text direction.

  • alignAnchoredAlign

    Default "center"

    Alignment along that side.

  • sideOffsetnumber | ((data: { side: AnchoredSideRequest; align: AnchoredAlign; anchor: { width: number; height: number }; positioner: { width: number; height: number } }) => number

    Default 8

    Gap between anchor and popup, px or a function of the placement.

  • positionMethodPositionStrategy

    absolute (default) follows the page while it scrolls; fixed places in the viewport.

  • alignOffsetnumber | ((data: { side: AnchoredSideRequest; align: AnchoredAlign; anchor: { width: number; height: number }; positioner: { width: number; height: number } }) => number

    Default 0

    Shift along the anchor's edge.

  • collisionBoundaryCollisionBoundary

    Default "clipping-ancestors"

    What the popup must stay inside.

  • collisionPaddingnumber | Partial<PlacementPadding>

    Default 5

    Space kept from the boundary's edges.

  • arrowPaddingnumber

    Default 5

    Space kept between the arrow and the popup's corners.

  • disableAnchorTrackingboolean

    Default false

    Do not follow the anchor after the first placement.

  • collisionAvoidanceCollisionAvoidance

    Flip, shift or neither, per axis.

  • lazyFlipboolean

    Default false

    Flip lazily: once the popup is placed, the side it settled on is the side it starts from, so it flips back only when that side no longer fits (a list that filters while open). Base UI applies this inside its Combobox positioner only; here every positioner takes it.

  • adaptiveOriginboolean

    Default false

    Keep --transform-origin right while the popup resizes or morphs: a popup on the left or top side is written from its far edge (right / bottom), so a size transition grows toward the anchor. Only a popup with a CSS transition is affected. Base UI turns this on when the popup has a Viewport part; here every positioner takes it.

Plus render, and className / style as functions of the part's state, and every <div> prop.

ToastProvider

Holds the toasts (renders no element): wrap the app, then raise toasts with useToastManager(), or pass a toastManager made by createToastManager().

  • childrenReact.ReactNode

    The app, including the viewport and every part that calls useToastManager().

  • timeoutnumber

    Default 5000

    The default amount of time (in ms) before a toast is auto dismissed. A value of 0 prevents it being dismissed automatically.

  • limitnumber

    Default 3

    The maximum number of toasts that can be displayed at once. When the limit is reached, the oldest toast is marked limited to make room for the new one.

  • toastManagerToastManager<any>

    A global manager for toasts to use outside of a React component.

Toasts

Every toast the provider holds, drawn the usual way: type icon, title, description, action, close. Pass swipeDirection and the like through rootProps.

  • rootPropsOmit<ToastPrimitive.Root.Props, "toast">

    Props for every toast's root (swipeDirection, a className), except the toast itself.

ToastTitle

The toast's title in medium weight; it shows the toast's title.

Plus render, and className / style as functions of the part's state, and every <h2> prop.

ToastViewport

The region the toasts live in: fixed to the bottom right (move it with className). F6 moves focus into it.

Plus render, and className / style as functions of the part's state, and every <div> prop.

Hooks and functions

  • TOAST_TYPE_LOOK

    The one icon and tone table of the toasts: Toasts here and the feedback kit's toaster both read it, so a change of glyph or colour reaches both stacks. Look a type up with {@link toastTypeLook}.

  • TOAST_TYPE_NAMES

    The toast types both stacks know, in gallery order. loading spins (and stops under reduced motion).

  • toastTypeLook(type: string | undefined) => ToastTypeLook | undefined

    The look of a toast type, or undefined for a type neither stack knows (the primitives' type is free text).

  • createToastManager<T extends ToastFields = ToastFields>() => ToastManager<T>

    Makes a toast manager you can raise toasts with from outside React; hand it to <ToastProvider toastManager={manager}>.
