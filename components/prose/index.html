Prose

One look for rendered markdown, rich text and CMS HTML: headings, lists and task lists, quotes, links, inline code, pre, kbd, images, figures and tables on the table slot, in three sizes, mirrored in right-to-left text, with not-prose to keep a part out. The editors and ai-chat kits draw through it.

Source: @kitora/ui (the primitive the kits compose)

02HTML article

A long CMS article at size="md" drawn as an <article> through render: a figure with a caption, a table on the table slot and a code block, both scrolling inside themselves on a phone.

Caching the dependency graph

Cold builds spent most of their time walking the same imports again. The graph is now written to disk after each run and read back on the next one, keyed by the lockfile and the compiler version, so a change to either starts fresh.

Results

Median of ten runs on the same machine, in seconds:

PackageBeforeAfterSaved
ui14.26.157%
datagrid22.89.459%
editors18.58.952%

Turning it off

Set cache: false in the build config, or pass the flag once:

// build.config.ts
export default defineConfig({
  cache: process.env.CI ? false : { dir: ".cache/graph", key: ["pnpm-lock.yaml", "typescript"] },
})

When to clear it

After switching branches with a different lockfile nothing needs clearing: the key changes. Clear it by hand only when a build reads a stale import, and report that as a bug.

03Sizes

sm (13px, the compact default the editors and ai-chat kits use), md (14px) and lg (16px): type, code, tables and the gap between blocks scale together.

Size sm

The body, headings, code and tables scale together; the gap between blocks grows with the size. Inline code stays a step smaller.

  • Compact panels use sm
  • Reading views use md or lg

Size md

The body, headings, code and tables scale together; the gap between blocks grows with the size. Inline code stays a step smaller.

  • Compact panels use sm
  • Reading views use md or lg

Size lg

The body, headings, code and tables scale together; the gap between blocks grows with the size. Inline code stays a step smaller.

  • Compact panels use sm
  • Reading views use md or lg

Props

Prose

Styles a tree of raw HTML (markdown output, rich text, CMS content): headings, paragraphs, links, lists and task lists, blockquotes, inline code, pre, kbd, hr, images, figures and tables. size is sm (13px, the compact default), md (14px) or lg (16px); render draws it as another element (<article>). Give anything that must keep its own look the not-prose class. A host that only takes a class string (a ProseMirror root) uses proseVariants.

  • size"sm" | "lg" | "md" | null

    Default "sm"

    The text scale: sm 13px (compact), md 14px, lg 16px; headings, code and spacing follow it.

Plus render, and className / style as functions of the part's state, and every <div> prop.

Hooks and functions

  • proseVariants(props?: ({ size?: "sm" | "lg" | "md" | null | undefined; } & ClassProp) | undefined) => string

    The class string Prose draws, for a host that only takes a class (a ProseMirror root): proseVariants({ size: "md" }).
