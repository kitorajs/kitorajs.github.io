No build step

An import map, esm.sh and Tailwind's browser build: one HTML file.

A page with no build step: the browser loads React and Kitora as ES modules from a CDN, and Tailwind's browser build generates the classes the components use at runtime. Good for prototypes, demos and pages that cannot run a bundler; an app with a build ships far less.

The page needs three parts:

  • An import map naming React and React DOM once. Every module that imports react gets that copy, so hooks work across the library and your own code.
  • The library from esm.sh, one entry per import, with ?external=react,react-dom: esm.sh leaves those imports to the import map instead of bundling a second React. Pin the version.
  • Tailwind v4's browser build (@tailwindcss/browser), the design tokens in a <style type="text/tailwindcss"> block (what @kitora/theme's exporter writes, minus its first line), and the primitives' behaviour stylesheet fetched into a second such block, since the browser build cannot import a URL.

The language switch works as in an app: LanguageProvider loads a built-in language's data from esm.sh when it is picked.

jsDelivr

jsDelivr's +esm serves the same modules, but it resolves each module's dependencies to exact versions when it first bundles that file, and an import map cannot redirect those URLs. React then loads once only while every file resolved the same React version as the import map names, so prefer esm.sh, whose external option leaves React to the import map. The page lives in the repository at examples/no-build. task recipes:smoke serves it as static files and checks it in a headless browser against a local esm.sh that holds the packed packages: one React instance, the button styled, the dialog working, dark mode, a design-language switch and a clean console. After a release, task recipes:smoke -- --only no-build --live runs the same checks against the real esm.sh and jsDelivr.
