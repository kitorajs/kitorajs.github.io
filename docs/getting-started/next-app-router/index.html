Next.js App Router

Server components render Kitora directly; a client form posts to a server action.

The App Router renders pages as React Server Components. Every Kitora module that needs the browser (hooks, context, refs, event handlers) starts with "use client", and every other one (core logic, data, server helpers) does not, so a server component imports both kinds directly: no wrapper files, no transpilePackages.

pnpm add @kitora/ui @kitora/primitives react react-dom tailwindcss @kitora/theme

Tailwind v4 reaches Next.js through PostCSS: add tailwindcss and @tailwindcss/postcss as dev dependencies.

  • app/page.tsx is a server component. It renders Button and Dialog (client components) and Alert (a server-safe one) straight from their entries, and a client form of its own.
  • app/contact-form.tsx is a client component: React's useActionState posts the form to the server action in app/actions.ts, and the fields are Kitora's.
  • app/globals.css imports the tokens gen-tokens.mjs writes, the primitives' behaviour stylesheet and one line per ui module.

A function cannot cross from a server component into a client one, so a component that needs an event handler or a render function belongs in a client file of yours, as the form does here. The @kitora/form server helpers (@kitora/form/server) run in a server action as they are.

This app lives in the repository at examples/next-app-router. task recipes:smoke installs it from the packed packages, runs next build and next start, and checks the server-rendered HTML, the hydrated dialog, dark mode, the form's round trip through the server action and a clean console.

Relies on: examples/next-app-router, scripts/packages-use-client.mjs, scripts/recipes-smoke.mjs
