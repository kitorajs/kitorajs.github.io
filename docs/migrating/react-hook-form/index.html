Migrating

From React Hook Form

useForm, register and Controller to the form engine's fields, rules and arrays.

React Hook Form registers inputs you draw yourself; the form engine in @kitora/form gives you fields that draw their own label, control and error. This page moves one form across: an invite with two inputs, a custom control, a list of guests and rules written next to the fields, no resolver.

pnpm add @kitora/form @kitora/primitives react react-dom tailwindcss y-protocols yjs

Before and after

The Before form uses useForm, register for the inputs, Controller for a radio group, useFieldArray for the guests and handleSubmit. Its error lines and their aria-invalid and aria-describedby wiring are written by hand.

Before

The After form is the same form on the engine. Each field takes the name of its value and shows its own error.

After

A test drives both forms with one script: leave a field empty, type a bad email and fix it, add a guest, submit with errors, fill everything in, add and remove guests, submit. After every step both show the same controls with the same names, values and invalid states, the same error messages linked to their controls, and the same buttons; a failed submit shows every message and moves focus to the first field in error; and both submit the same values.

For a control the catalogue does not have, useField(name) gives you its value, setter, blur handler and error, the way useController does. The gallery's migration page has more pairs: watched values, server errors and conditional fields.

What is different

When a field is checked. validateOn: "blur" checks a field when it loses focus, and revalidateOn: "change" checks it on each keystroke while it shows an error. RHF's onTouched checks on every keystroke once the field was left, even when it has no error. So after a valid email was left, typing a bad one shows the error at once in RHF and on the next blur in the engine.

Focus when rows change. RHF's append moves focus into the new row; FieldArray.Add keeps focus on the Add button. After a Remove, RHF leaves focus nowhere (the button is gone); FieldArray moves it to the first control of the row that took its place, or to Add when no row is left.

The forms guide goes further with the engine: cross-field rules, row bounds and reordering, and checks that ask your server.
