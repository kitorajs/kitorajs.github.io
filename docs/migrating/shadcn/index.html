Migrating

From shadcn/ui

The same component names and props, without copying the source into your app.

@kitora/ui has the shadcn/ui component names and props, one entry per component. The difference is where the code lives: shadcn/ui copies each component's source into your app, on Radix with cva variants and Tailwind classes; Kitora ships them as a package on its own primitives, so you import them and copy nothing.

Before and after

The Before is a screen as a shadcn/ui app has it, with the copied Button, Checkbox, Label and Dialog files folded into one example. The After is the same screen on kitora: the JSX is the same, only the imports change.

Before

After

The two behave the same: the checkbox toggles from the box, the label and Space, and posts updates=on with the form; the dialog opens by mouse, Enter and Space, moves focus to its first button, keeps Tab inside, and closes on Escape, Cancel or the corner button with focus back on the trigger. The page's test drives both with the same clicks and keys and compares what a person and a screen reader meet after every step.

Moving over

Install the package; the install page shows the CSS imports your stylesheet needs beside it.

pnpm add @kitora/ui @kitora/primitives react react-dom tailwindcss
  1. Change the imports. @/components/ui/dialog becomes @kitora/ui/dialog, @/components/ui/checkbox becomes @kitora/ui/checkbox, and so on. The names stay: Dialog, DialogTrigger, DialogContent, DialogHeader, DialogFooter, DialogTitle, DialogDescription, DialogClose, Checkbox, Button, Label.
  2. Keep asChild. Button, DialogTrigger and DialogClose take asChild as shadcn/ui does. They also take render, the primitives' spelling of the same thing, which takes the element as a prop instead of as the only child.
  3. Delete the copied files once nothing imports them (components/ui/* and the cn helper, which @kitora/ui/utils also exports).

What changes

State attributes. Radix writes one data-state attribute; Kitora writes one attribute per state. A class written for Radix needs the new name:

shadcn/ui (Radix)Kitora
data-[state=checked]:data-checked:
data-[state=unchecked]:data-unchecked:
data-[state=open]:data-open:
data-[state=closed]:data-closed:

The look. shadcn/ui's look is the class strings in your copied files, so restyling means editing them. Kitora's components read the active design language: the dialog's radius, shadow and backdrop come from the dialog slot, and the checkbox's size, radius and fill from the checkbox slot, so one language restyles every dialog and checkbox at once. You can still pass className. Design languages explains the slots, and the languages gallery switches them live.

A few extras. Checkbox draws its own label and description with label and description; DialogContent names its corner button with closeLabel, takes size, and has a DialogBody part for long content. Dialog, Checkbox and Button list every prop.

To go one level down, to the unstyled parts these components are built on, see From Radix.

Relies on: packages/ui/src/dialog.tsx, packages/ui/src/checkbox.tsx, packages/ui/src/button.tsx, packages/ui/src/label.tsx, packages/ui/src/utils.ts, src/kit/components/__tests__/rebuild/harness.tsx, src/docs/examples/__tests__/radix-equivalence.ts, src/docs/examples/__tests__/migrating-shadcn.test.tsx, src/docs/examples/__tests__/migrating-radix.test.tsx
