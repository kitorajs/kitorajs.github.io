Migrating

From Base UI

The same parts, props and data attributes: change the import.

Kitora's headless parts in @kitora/primitives were built to replace Base UI 1.4.1, and they keep its part names, its props and its data attributes on purpose, so that no class string changed when a part moved over. Moving a Base UI app is mostly a change of import.

This page has no "Before" example: Base UI cannot be installed in the Kitora repo, so the comparison that proves the two behave the same is the record taken before Base UI was removed (below).

Change the import

Each Base UI part comes from its own path, @base-ui/react/<part> (or from the @base-ui/react barrel). In Kitora they all come from one entry, @kitora/primitives/react, under the same names: Menu from @base-ui/react/menu becomes Menu from @kitora/primitives/react, and so do Popover, Dialog, Tabs, Select and the rest. A compound part is a namespace of parts there too (Menu.Item), and a single component stays one (RadioGroup, ToggleGroup). The helpers move the same way: useRender, mergeProps and DirectionProvider are exports of that entry.

pnpm add @kitora/primitives react react-dom

Inside the namespace nothing is renamed. Menu.Root, Menu.Trigger, Menu.Portal, Menu.Positioner, Menu.Popup and Menu.Item take the props they took in Base UI (sideOffset, disabled, checked with onCheckedChange, render to swap the element), and they write the same attributes your classes already style: data-popup-open on the trigger, data-highlighted on the item under the keyboard or pointer, data-disabled, data-checked.

After

Last action: Nothing yet. Favourite: no.

Try it: focus Song and press the down arrow. The menu opens on its first item; Enter runs the highlighted item, closes the menu and gives focus back to the trigger. Download is disabled and never runs. Ticking Favourite keeps the menu open, and Escape closes it.

The behaviour stylesheet defines Tailwind variants for the boolean states (data-open:, data-checked: and the others in the README's table) and the enter and exit animations the styled packages use. If your classes use them, put these lines in the CSS file your Tailwind build reads:

@import "tailwindcss";
@import "@kitora/primitives/styles.css";
@import "@kitora/primitives/tailwind.css";

How the sameness was checked

Before Base UI left the repo, each part the migration moved over had a spec suite that ran once against Base UI 1.4.1 and once against Kitora's part, and every case passed on both sides. The package README records each suite's result in its section "Parity at removal", together with the real-browser comparisons of popup placement, hover and menus. The suites still run, now against Kitora alone. A separate test pins the part list of every popup family (Popover, Menu, Select, Combobox, Toast and the others) against Base UI 1.4.1's published list, so a part Base UI has and Kitora lacks fails that test.

What is different

A few differences are deliberate, each pinned by a kitora-only test so it is not "fixed" back. The README lists them all in its section "Deliberate differences from Base UI"; the ones you are most likely to notice:

PartIn Kitora
RadioGroupSpace checks the focused radio, a disabled radio is never the tab stop, and the tab stop follows a value changed from outside (the WAI-ARIA pattern).
CheckboxA checkbox that is both checked and indeterminate activates to checked.
TooltipThe popup has the tooltip role and the trigger points at it with aria-describedby while it is open. Escape closes the newest tooltip or preview card only, so a dialog under it stays open.
MenuA close is reported to onOpenChange once.
Toolbar, Menubar, NavigationMenuHome and End jump to the first and last item.
Select, ComboboxThe separator is presentational, so the list passes axe; Select also moves a page with PageUp and PageDown.
Combobox, NavigationMenuLeft and Right on a combobox's chips, and the arrow that opens a vertical navigation menu's panel, follow right-to-left text.
DrawerOne close request per document goes to the top-most layer, so two drawers never both close.

And a few additions Base UI 1.4.1 does not have, all optional, so Base UI code works without them:

  • disallowEmptySelection on ToggleGroup, so the last pressed toggle cannot be pressed off.
  • enableHomeAndEndKeys on RadioGroup.
  • focusableWhenDisabled on menu and select items, to step over disabled items.
  • lazyFlip and adaptiveOrigin on every anchored positioner.
  • Rating, a part Base UI does not have, and the searchable menu (Menu.FilterProvider) from a later Base UI preview.

If you used Base UI through shadcn/ui's Base UI flavour, the styled components in @kitora/ui are the shorter path: see from shadcn/ui. The primitives contract explains the names and attributes every part shares.
