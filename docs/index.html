Documentation

Kitora docs

Guides to start, to understand how Kitora is put together and to do one task at a time. The API of every component is the generated reference on /components and of every package on /docs/packages; the deep, feature-by-feature galleries are on /kits.

Getting started

13 docs

Install, styles, providers, a recipe per framework (or none) and a first form and data table.

  • Install

    The packages, the install line, the CSS your Tailwind build reads and the design tokens.

  • Providers

    The four providers an app wraps once at its root, and what each one is for.

  • Server rendering

    The components render on the server; a boot script keeps a saved design language from flashing.

  • Vite and React

    A single-page app on Vite and Tailwind v4: the tokens, the stylesheet and the components.

  • Next.js App Router

    Server components render Kitora directly; a client form posts to a server action.

  • Next.js Pages Router

    Server-rendered pages that hydrate, with the stylesheet in _app.

  • React Router

    Framework mode (the successor of Remix): server-rendered routes on Vite.

  • Astro

    Kitora inside a React island, prerendered and hydrated.

  • No build step

    An import map, esm.sh and Tailwind's browser build: one HTML file.

  • Module formats

    ES modules only: why there is no UMD or CommonJS build, and what to use instead.

  • A first form

    Fields, validation, submit and status with the form engine.

  • A first data table

    Columns, an adapter and sorting with the data grid.

  • Bundle size

    What each import costs, from the size budgets every release is held to.

How Kitora is put together: layers, the primitives contract, design languages and form binding.

  • Layers and tiers

    core, dom, react and ui inside a package, and the tiers packages build on.

  • The primitives contract

    Part names, render, controlled and uncontrolled state, data attributes and form binding.

  • Design languages

    Tokens, component slots and layout presets that restyle every component live.

  • Form binding

    name, hidden inputs and Field: every control works in a plain form.

  • Forms

  • The data grid

    Columns, selection, editing, cell ranges and the clipboard.

  • Theming and your own design language

  • Performance and lazy entries

Migrating

4 docs

From shadcn/ui, Radix, Base UI and React Hook Form, each with a before and after that behave the same.

  • From shadcn/ui

    The same component names and props, without copying the source into your app.

  • From Radix

    Radix parts to Kitora's primitives: names, render instead of asChild, the data attributes.

  • From Base UI

    The same parts, props and data attributes: change the import.

  • From React Hook Form

    useForm, register and Controller to the form engine's fields, rules and arrays.
