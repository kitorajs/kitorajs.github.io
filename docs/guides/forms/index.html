Forms

From a simple form to rules, field arrays and async validation with the form engine.

This guide starts where a first form ends: useForm, Form, fields with a name, and Form.Submit. It adds the three things most real forms need next, all from @kitora/form: rules that read other fields, a list of rows the person can grow and reorder, and a check that has to ask your server.

Rules and cross-field rules

A field's rules are a list built with v from kit<YourValues>(). Built-in rules cover length, ranges, patterns, email and URL; each takes the message to show. A rule can also read another field: v.matches("secret") (the name of the field to compare with) fails until the two values are equal.

validateOn: "blur" checks a field when it loses focus, and revalidateOn: "change" checks it again on every keystroke once it shows an error, so an error clears as soon as the value is fixed. A cross-field rule runs again whenever the field it reads is checked: change the password after confirming it, and the confirm field shows the mismatch.

Rules that read another field

Try it: type a short password and leave the field, fix it, confirm it, then change the password again and leave the field. Submit stays held back until every rule passes.

Field arrays

FieldArray repeats its children once per row of an array value. Inside it, a name that starts with a dot is relative to the row, so .name is guests.0.name in the first row. FieldArray.Add appends newRow, and FieldArray.RowActions gives each row its Remove and move up / move down buttons, named for the row ("Remove guest 2").

min and max turn Remove and Add off at the bounds, with the reason on the button. reorder adds a handle to each row: press Space on it, move with the arrow keys, and press Space again to drop. A rule on the array itself, like v.unique(".email"), compares the rows with each other.

Async validation

A check that asks your server is a named validator: you register its code in a registry with catalogRegistry().validator(name, { fn }), pass the registry to useForm, and refer to it in rules with v.op(name). Its function gets the value and an AbortSignal, and returns a message when the value fails.

With async: { debounceMs } the check waits until typing pauses, so fast typing asks once, for the last value. A newer check aborts the one before it, and a late answer to an aborted check is dropped. While a check runs, the field is marked busy (aria-busy). Submit runs the check too, and holds back while the name is taken.
