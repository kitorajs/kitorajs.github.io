Performance and lazy entries

Import the smallest entry, load heavy engines lazily, and keep big lists fast.

A page pays for the code it imports and for the rows it renders. Four habits keep both small: import the narrowest entry, load heavy engines only where they are used, let your bundler drop what you do not use, and render only the rows on screen.

Import the smallest entry

Every package is split into entries: its layers (core, dom, react, ui) and, in the larger kits, one entry per component or per engine. Import from the narrowest entry that has what you need. The collections kit, for example:

  • @kitora/collections162.4 kB gzip
  • @kitora/collections/core7.0 kB gzip
  • @kitora/collections/dom0.8 kB gzip
  • @kitora/collections/react24.4 kB gzip
  • @kitora/collections/ui162.6 kB gzip

The headless hook useVirtualList comes from @kitora/collections/react (24.4 kB gzip); the styled VirtualList from @kitora/collections/ui (162.6 kB gzip). Where a package's root re-exports its layers, a named import from the root costs the same as one from the layer, and the size check measures that on every release. Bundle size explains the budgets.

Load heavy engines on demand

The big third-party engines (the code editor, rich text, maps, syntax highlighting, collaboration) live in entries of their own, so a page pays for one only where it uses it. The size check fails any other entry that pulls one of them in up front.

Yjs is in the two collaboration entries only: @kitora/collab and the form engine's other entries never import it, so a page that does not collaborate never ships it. A map's engine loader is the loader prop, which you can swap to preload the engine or to stub it in tests.

The lazy editors take the same props as the eager ones and draw the editor's frame at once, marked busy, so the page does not jump when the engine arrives.

For a heavy part of your own, do the same with lazy and Suspense from React and an import() of its entry: the bundler puts it in a chunk of its own, which loads the first time the part renders. The site header opens the design-language customizer this way.

A panel loaded the first time it opens

Let the bundler drop what you do not use

Every package's package.json lists only its CSS files under sideEffects, so your bundler drops any module none of whose exports you use. The build also marks top-level calls such as createContext as pure, so using one export of a module does not keep the rest of it alive; a release check bundles each built module on its own to prove the marks are there.

Render only the rows on screen

DataGridVirtual sits inside the same providers as DataGrid, takes a height and a fixed rowHeight, and mounts only the rows in its height, inside a scroll body sized for all of them. The virtual grid demo runs it with search, filters and sorting on.

Ten thousand rows in a virtual grid

VirtualList does the same for any list: rows of one height with rowHeight, or rows of different heights with estimateSize, each measured once it mounts. Scroll it from code with handleRef. The collections kit's listbox and tree view use the same window (ten thousand rows).
