Layers and tiers

core, dom, react and ui inside a package, and the tiers packages build on.

Layers inside a package

A package splits into entries that build on each other, from plain data to styled parts:

  • core: state and maths with no DOM and no React, so a server, a script or another renderer can run it;
  • dom: browser behaviour (pointer, focus, measuring) on top of core;
  • react: hooks and unstyled parts on top of both;
  • ui: the styled parts, usually the package's root entry.

A layer imports only the layers below it, and the packages' layer tests fail an import that reaches upward. Import the lowest layer that does the job: the pickers' colour maths costs a fraction of the picker.

Tiers between packages

Packages build on each other the same way. @kitora/primitives is the bottom: it depends on no other Kitora package. @kitora/ui builds on it, and every kit sits above the packages it uses. Dependencies only point down a tier, so a package never pulls in one built on top of it.

  • Tier 0primitives
  • Tier 1ui
  • Tier 2keyboard, theme
  • Tier 3charts, dnd, i18n, spreadsheet, terminal
  • Tier 4flow, overlay
  • Tier 5display, maps, upload, windows
  • Tier 6collab, collections, dock
  • Tier 7editors, pickers, search, sidebar, tabster, task-list
  • Tier 8chat, commerce, datagrid, feedback, form, scheduling, shell, whiteboard
  • Tier 9ai-chat, auth, form-builder, tour
