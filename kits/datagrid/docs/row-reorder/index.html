Row reorder

Drag rows / cards to a new position. The whole system is layered so you can switch the drag feel, the handle placement, the layout, or replace any piece — without touching the others.

Architecture

Three layers, three swap points:

  1. Hook flavor — picks what follows the pointer. Both are presets over one engine, useRowReorderDnd, built on the in-repo DnD kit (@kitora/dnd): pointer, touch long-press, keyboard (Space on a focusable grip, arrows, Space; Escape cancels), auto-scroll near the scroll container's edge, and screen-reader announcements through the kit's live region. No provider is needed: the hook owns its kit instance.
    • useDataGridRowDragReorder — a small "N rows" pill follows the pointer. Used by the <DataGrid> table view (a <tr> cannot be cloned outside its table).
    • useDataGridFreeFlowDragReorder — a clone of the row follows the pointer (Trello / Linear feel); a selected batch shows as a stack of up to three clones with a count badge. Used by cardsLayout + <DataGridVirtual> (and mediaGridLayout through useMediaGridDragReorder). Vertical rows cap the clone at 360px.
  1. Drag handle mode — picks where the drag gesture originates.
    • 'whole-row' / 'whole-card' — pointerdown anywhere on the row lifts it.
    • 'icon' — the layout renders a built-in <GripVertical> handle. Only pressing the handle drags. Row body stays clickable.
    • 'none' — no auto-handle. You mount <DataGridRowDragHandle rowId> inside a cell renderer / custom slot. Multiple handles per row supported.
  1. Adapter dispatch — picks which mutator runs.
    • dispatchRowMove(mutators, ids, beforeId) — auto-prefers bulkMoveRows over sequential moveRow calls. Caller of either hook just passes this helper as onMove.

All three are independently configurable. The result: any combination users can think of is wired.

30-second mount

// Table layout (pill hook + built-in grip column; Space on the grip drags by keyboard)
<DataGrid<User> columns={cols} enableRowReorder />

// Cards layout (free-flow hook + whole-card drag)
<DataGridView
  layouts={[cardsLayout<User>({ enableRowReorder: true })]}
/>

// Cards layout — grip icon mode
<DataGridView
  layouts={[
    cardsLayout<User>({
      enableRowReorder: true,
      dragHandle: 'icon',
    }),
  ]}
/>

// Virt rows
<DataGridVirtual<User>
  columns={cols}
  enableRowReorder
  dragHandle="icon"      // (default)
  // OR dragHandle="whole-row"
/>

All of the above require the adapter to implement at least one of moveRow / bulkMoveRows. When neither is present, drag handlers auto-disable (no UI lies about being interactive).

Drag handle modes

dragHandle is the lever every reorder-capable layout exposes:

ModeWhere pointerdown starts a dragVisual
'whole-row' / 'whole-card'Anywhere on the row / cardRow body shows cursor: grab
'icon'Only on the auto-rendered <GripVertical>Handle shows cursor: grab; row body stays auto
'none'Only on your custom <DataGridRowDragHandle> instancesYou control the visual

When you pick 'whole-row', an internal 5px movement threshold disambiguates click vs drag — single clicks open / select the row normally; only sustained motion lifts it. When you pick 'icon' (or 'none' with custom handles), there's no ambiguity — every pointerdown on the handle becomes a drag attempt.

Defaults per layout:

LayoutDefault dragHandleDefault rationale
<DataGrid> (table)'icon' (built-in grip column)Rows are wide; clicking anywhere = drag would conflict with text selection in cells
<DataGridVirtual>'icon'Same as above
cardsLayout'whole-card'Cards are bounded by their grid cell; "lift the card" is a natural gesture
mediaGridLayout'whole-card'Gallery feel matches Photos / Pinterest

<DataGridRowDragHandle> — handles anywhere

The drop-in component. Place inside any cell renderer or custom slot.

import {
  DataGridRowDragHandle,
  defineColumns,
} from '@kitora/datagrid'
import { GripVertical } from 'lucide-react'

const columns = defineColumns<User>()([
  {
    id: 'grip',
    header: '',
    cell: (r) => (
      <DataGridRowDragHandle rowId={r.id}>
        <GripVertical className="size-3.5" />
      </DataGridRowDragHandle>
    ),
  },
  { id: 'name', header: 'Name', cell: (r) => r.name },
  // ...
])

<DataGridVirtual<User>
  columns={columns}
  enableRowReorder
  dragHandle="none"   // disable the auto-grip column; you're rendering your own
/>

Multiple handles per row

Spread <DataGridRowDragHandle rowId> as many times as you want. Each one is a fresh drag origin point pointing at the same row.

const columns = defineColumns<Task>()([
  {
    id: 'grip-left',
    header: '',
    cell: (r) => <DataGridRowDragHandle rowId={r.id}><GripVertical/></DataGridRowDragHandle>,
  },
  { id: 'title', header: 'Title', cell: (r) => r.title },
  {
    id: 'grip-right',
    header: '',
    cell: (r) => (
      <DataGridRowDragHandle rowId={r.id} aria-label="Move row">
        <Move className="size-3.5" />
      </DataGridRowDragHandle>
    ),
  },
])

asChild — turn any button into a handle

asChild (Radix-style) merges drag handlers onto your child element instead of wrapping it in a <span>. Use it to make existing <Button> / icons / links draggable without extra DOM:

<DataGridRowDragHandle rowId={r.id} asChild>
  <Button size="sm" variant="ghost">
    <Move className="size-3.5" />
    Move
  </Button>
</DataGridRowDragHandle>

The button receives the kit's handle marker (data-dnd-handle) + data-drag-handle="". Clicks still fire onClick; a press only becomes a drag past the kit's 3px mouse threshold (a 250ms long-press on touch). The span form is focusable (role="button", tabIndex=0), so Space on it picks the row up. The handle must sit inside the row element that spreads itemProps(rowId).

Graceful no-op

<DataGridRowDragHandle> reads the layout's reorder context. When that context isn't published (reorder not on, layout doesn't support it, or dragHandle resolves to off), the component renders children pass-through with no handlers. So you can leave it in cell renderers permanently — it lights up when reorder is on and quietly disappears when off.

Hook-level API (for custom layouts)

If you're building your own layout, pull the hook directly:

import {
  useDataGridFreeFlowDragReorder,
  dispatchRowMove,
  useDataGrid,
  useDataGridUI,
  DataGridReorderProvider,
  DataGridRowDragHandle,
} from '@kitora/datagrid'

function MyGalleryLayout({ rows }) {
  const { mutators, getRowId } = useDataGrid()
  const { selectedIds } = useDataGridUI()
  const rowIds = rows.map(getRowId)

  const {
    itemProps,
    handleProps,
    isDragSource,
    dropMark,
    mode,
  } = useDataGridFreeFlowDragReorder({
    enabled: true,
    rowIds,
    selectedIds,
    orientation: 'horizontal',
    mode: 'handle',    // or 'whole-row'
    onMove: (ids, beforeId) => dispatchRowMove(mutators, ids, beforeId),
  })

  return (
    <DataGridReorderProvider
      value={{ handleProps, isDragSource, mode }}
    >
      {rows.map((r) => {
        const id = getRowId(r)
        return (
          // itemProps carries the kit's registration `ref`: spread it on the row element.
          <div key={id} data-row-id={id} {...itemProps(id)}>
            <DataGridRowDragHandle rowId={id}>
              <GripVertical />
            </DataGridRowDragHandle>
            {/* row body */}
          </div>
        )
      })}
    </DataGridReorderProvider>
  )
}

Five touchpoints, no further plumbing — descendant cells can mount <DataGridRowDragHandle> freely.

Selection-aware drag

Both hook flavors are selection-aware: if the dragged row is part of the active selection (selectedIds), the whole selection moves — preserving its document order. Otherwise just the single dragged row moves.

Visually, free-flow shows a stack of clones with a count badge (the kit's stackedPreview); the table's pill reads "N rows". The batch is chosen at press time through the kit's selection option, so a keyboard drag moves the same batch as a mouse drag.

Dispatch:

  • ids.length > 1 + adapter has bulkMoveRows → one server round-trip.
  • Otherwise → sequential moveRow(id, beforeId) calls, serialized so anchor order is stable.

Adapter contract

interface DataGridAdapter<TRow> {
  // ...required methods
  moveRow?(rowId: string, beforeRowId: string | null): MaybePromise<void>
  bulkMoveRows?(rowIds: string[], beforeRowId: string | null): MaybePromise<void>
}

beforeRowId semantics — drop in front of this row, or null to append at end.

The grid auto-hides drag affordances if neither is implemented; inspectCapabilities(adapter).moveRow / bulkMoveRows exposes this for custom UI.

Two flavors of drag — when to pick which

Pill (useDataGridRowDragReorder)Free-flow (useDataGridFreeFlowDragReorder)
Preview"N rows" pill under the pointerClone of the row; a stack with a count badge for a batch
ImplementationDnD kit (@kitora/dnd)DnD kit (@kitora/dnd)
Touch supportLong-pressLong-press
KeyboardSpace on a grip, arrows, SpaceSpace on a grip, arrows, Space
Wide rowsPill never smearsClone width capped (360px for vertical rows)
Used by<DataGrid> table<DataGridVirtual>, cardsLayout, mediaGridLayout

Both share the same { rowIds, selectedIds, orientation, onMove } shape and the same dispatchRowMove helper, and both return { itemProps, handleProps, isDragSource, dropMark, mode }. Swap between them by changing the import. Cross-window drops (a native HTML5 feature) are not supported by either.
