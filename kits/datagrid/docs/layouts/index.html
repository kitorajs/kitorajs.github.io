Layouts

Same data + adapter, different render. The grid ships four built-in layouts and accepts pluggable custom ones via DataGridLayout.

Layout idFactoryWhat it draws
table(built-in)Classic rows + columns — sort header, drag-resize, pin, inline edit, group-by sections, tree expansion
cardscardsLayout()Responsive grid of cards — same data + selection + row actions
kanbankanbanLayout()Group-by-column board with drag-to-column rerouting
media-gridmediaGridLayout()Google-Photos-style gallery (see MediaGrid)

Switch by setting useDataGridUI().layoutId, or mount the built-in toolbar control <DataGridLayoutSwitcher layouts={[...]} />.

<DataGridView> — the renderer

Use <DataGridView> (not <DataGrid> directly) to support non-table layouts. It reads useDataGridUI().layoutId and dispatches:

import {
  DataGridView,
  cardsLayout,
  kanbanLayout,
  mediaGridLayout,
  DataGridLayoutSwitcher,
} from '@kitora/datagrid'

const layouts = [
  cardsLayout<User>({
    headlineColumnId: 'name',
    bodyColumnIds: ['role', 'status', 'team'],
  }),
  kanbanLayout<User>({
    headlineColumnId: 'name',
    groupBy: (row) => row.status,
    patchFor: (key) => ({ status: key }),
    columns: [
      { key: 'active', label: 'Active' },
      { key: 'invited', label: 'Invited' },
      { key: 'paused', label: 'Paused' },
    ],
  }),
]

<DataGridLayoutSwitcher layouts={layouts} />
<DataGridView columns={columns} layouts={layouts} />

'table' is always present; passing layouts={[]} shows only the table option.

cardsLayout(options)

cardsLayout<TRow>({
  headlineColumnId?: string      // default: first column
  subheadColumnId?: string
  bodyColumnIds?: string[]
  minCardWidth?: string          // default '16rem'
  footer?: (row) => ReactNode
  enableRowReorder?: boolean     // default false — see /docs/datagrid/row-reorder
  dragHandle?: 'whole-card' | 'icon' | 'none'  // default 'whole-card'
})

Same data flow as the table. Cards inherit row actions, context menu, selection, group-by sections. When enableRowReorder is on, the cards become drag sources via the pointer-driven free-flow hook — the dragged card visually lifts and follows the cursor. dragHandle picks where the drag gesture originates (full guide).

kanbanLayout(options)

kanbanLayout<TRow>({
  groupBy: (row) => string                 // key for the column the row belongs in
  patchFor: (key) => Partial<TRow>         // patch dispatched on drop
  columns: KanbanColumnDef[]               // ordered columns
  headlineColumnId?: string
  subheadColumnId?: string
})

Drag a card to another column → calls mutators.updateRow(rowId, patchFor(targetKey)). Auto-shows "Drop here" zones for empty columns.

Opening a row from the keyboard

When onRowClick is set, every card (cardsLayout) and <DataGridVirtual> row is a Tab stop (a kanban board is one Tab stop whose arrows walk its cards), and pressing o on the focused card or row opens it, the keyboard twin of clicking it. Enter opens as well when the row has no drag; on a draggable row (enableRowReorder, or any kanban card) Enter and Space belong to the keyboard drag (they pick the row up and drop it), so o is the one key that works everywhere. Only a plain key counts: Shift, Alt, Ctrl and Meta chords are left to the browser and the host. Each row carries the keys in aria-keyshortcuts (o, or Enter o without drag) so screen readers announce them, and <DataGridShortcutsHelp> lists o with the other grid keys. The table layout keeps its own row semantics.

Custom layouts — DataGridLayout interface

interface DataGridLayout<TRow> {
  id: string
  label: string
  icon?: LucideIcon
  render: (ctx: LayoutCtx<TRow>) => ReactNode
}

LayoutCtx exposes everything you need to draw rows:

interface LayoutCtx<TRow> {
  rows: TRow[]
  columns: readonly DataGridColumn<TRow>[]
  loading: boolean
  fetching: boolean
  isFiltered: boolean
  getRowId: (row: TRow) => string
  density: 'compact' | 'comfortable'
  emptyState: ReactNode
  loadingState: ReactNode

  /* selection */
  selectedIds: string[]
  isSelected: (id: string) => boolean
  toggleSelected: (id: string, value?: boolean) => void

  /* row interactions */
  onRowClick?: (row: TRow) => void
  rowAccent?: (row: TRow) => string | undefined

  /* row actions */
  leftActions?: (row: TRow) => ActionItem[]
  rightActions?: (row: TRow) => ActionItem[]
  rightMenuActions?: (row: TRow) => ActionItem[]
  contextMenuActions?: (row: TRow) => ActionItem[]
}

Minimal custom layout:

const tableOfContents: DataGridLayout<Chapter> = {
  id: 'toc',
  label: 'TOC',
  render: ({ rows, isSelected, toggleSelected }) => (
    <ol className="space-y-1">
      {rows.map((r) => (
        <li key={r.id}>
          <button
            data-row-id={r.id}
            data-selected={isSelected(r.id) || undefined}
            onClick={() => toggleSelected(r.id)}
            className="block w-full text-left"
          >
            {r.title}
          </button>
        </li>
      ))}
    </ol>
  ),
}

Two conventions worth following:

  • Emit data-row-id={rowId} on each selectable element — lets useDataGridRubberBand + useDataGridLongPress work without extra config.
  • Use the provided emptyState / loadingState for parity with the built-in layouts.

Persisting the active layout

layoutId lives in useDataGridUI(). useDataGridUrlSync persists it to the query string out of the box, so a ?layout=kanban URL hydrates the right view on reload.

useDataGridUrlSync({ namespace: 'users' })

Saved views (<DataGridViewSelector>) snapshot the layout too — pick "Kanban draft" and you're back where you left it.
