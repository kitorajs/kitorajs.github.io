Filters

Declare your filter fields once via defineFilterFields() (an identity helper that preserves literal id types) and the grid gives you:

  • A two-stage filter picker (field → value editor)
  • Editable filter pills with operator + value
  • buildWhere(filters, fields) engine that merges every active pill into a single typed TWhere for your adapter
  • <DataGridFilterBar> that wires everything together

Define fields

import { defineFilterFields } from '@kitora/datagrid'

const filterFields = defineFilterFields<UserWhere>()([
  {
    id: 'status',
    label: 'Status',
    type: 'select',
    options: [
      { value: 'active',  label: 'Active' },
      { value: 'invited', label: 'Invited' },
      { value: 'paused',  label: 'Paused' },
    ],
    toWhere: ({ operator, value }) =>
      operator === 'eq' ? { status: value } : { status_not: value },
  },
  {
    id: 'team',
    label: 'Team',
    type: 'multi-select',
    options: ['Platform', 'Mobile', 'Design'].map((v) => ({ value: v, label: v })),
    toWhere: ({ operator, value }) =>
      operator === 'in' ? { team_in: value } : { team_not_in: value },
  },
  {
    id: 'tasks',
    label: 'Open tasks',
    type: 'number',
    toWhere: ({ operator, value }) => {
      if (operator === 'gte') return { tasks_gte: value }
      // … the rest of the numeric operators
    },
  },
])

Pass via the adapter:

const adapter = createInMemoryAdapter<User, UserWhere>({
  initial: rows,
  filterFields,
  // …
})

Override the operator list per field via operators: FilterOperator[]. A new filter starts on the type's smart default (smartDefaultOperator) when the field's list allows it, else on the first operator in that list (defaultOperatorForField(type, operators)).

Date values

A date filter stores the picked day's local midnight as a full ISO timestamp (new Date(y, m, d).toISOString()), and a date-range filter stores { from, to, preset } with from at local midnight of the first day and to at the last millisecond of the last day, so both ends are inclusive (presets store the same shape with their id in preset). Row values are usually full timestamps, so a date eq ("is") means "on this calendar day": the in-memory adapter matches any value from that local midnight to the day's last millisecond, inclusive, and dayBounds(cond.value) (exported from @kitora/datagrid) returns the same { from, to } ISO range for a toWhere to send, e.g. toWhere: (c) => ({ renews: c.operator === 'eq' ? dayBounds(c.value) : c.value }). The other date operators compare against the midnight instant. A new date filter starts on gte ("on or after"), the more common question.

The Users demo on the overview page has one filter of each: Joined (date-range) and Renews (date, next plan renewal):

{
  id: 'renews',
  label: 'Renews',
  type: 'date',
  group: 'Account',
  // the value is that day's local midnight as an ISO timestamp, so ≥ / ≤ compare cleanly with ISO strings
  toWhere: (cond) => ({ renews: cond.value }),
}

Mount the bar

import { DataGridFilterBar } from '@kitora/datagrid'

<DataGridFilterBar rightSlot={<DataGridSort options={sortOptions} />} />

The bar renders:

  • <FilterSearchInput> (the global search; controlled by adapter's search config)
  • "+ Filter" button → two-stage picker (field list → value editor)
  • One <FilterPill> per active filter: a group of two sibling buttons, the pill text (opens the operator + value editor) and × (removes the filter, named Remove <label> filter); Tab reaches both
  • "Clear" button when filters are dirty

buildWhere engine

Every field's toWhere(condition) partial is merged into one adapter-typed TWhere. The grid does this for you on every load — your adapter just receives query.where. To use the engine yourself:

import { buildWhere } from '@kitora/datagrid'

const where = buildWhere<UserWhere>(filters, filterFields)
// → { status_in: ['active'], team_in: ['Platform'], tasks_gte: 3 }

Search bridges in too — search.toWhere(q) is merged before filters.

Programmatic API

useDataGridUI() exposes:

const {
  filters,                 // FilterCondition[]
  addFilter,
  removeFilter,
  updateFilter,            // edit operator or value of an existing pill
  setFilters,              // replace all
  clearFilters,
} = useDataGridUI()

Saved views capture the full filters array — they restore on selection.
