Playground

Live at /kits/datagrid/playground.

The playground is to the datagrid what /kits/tasklists/headless is to the task-list kit — a single page with a control panel on the left, the rendered datagrid on the right. Flip a switch, change a radio, swap a dropdown — the right-hand grid reconfigures instantly. The provider pair stays mounted across every flip; only the UI primitives swap.

Why it exists

Three reasons:

  1. See pluggability in practice. The "every layer is replaceable" claim only feels real once you watch the same data + the same selection state render as a table, then as a kanban, then as a media-grid — without a single network re-fetch.
  2. Isolate one feature at a time. Bug reports often boil down to "does pagination still work when I disable selection?" The playground lets you reproduce that combo in three clicks.
  3. Demo every primitive. Eight pagination UI components, three modes, five layouts, ten toolbar widgets, six behavior toggles. The playground is the only place you can hit them all.

Seven control groups

1. Pagination mode (radio — single pick)

  • paged — <DataGridProvider paginationMode="paged">
  • infinite — bidirectional
  • numbered — offset / limit

Flipping mode automatically picks a sensible default for the next group so you never see an empty pagination slot.

2. Pagination UI (radio — mode-aware)

The options change with the active mode:

  • paged → <DataGridPagination> (or None)
  • infinite → <DataGridInfiniteAnchor> · <DataGridLoadMoreButton> (or None)
  • numbered → <DataGridNumberedPagination> alone, or the full kit (numbered + <DataGridFirstLastButtons> + <DataGridJumpToPage>)

3. Layout (radio — single pick)

Same rows, different renderer:

  • Table — <DataGrid>
  • Virt table — <DataGridVirtual> (windowing kicks in)
  • Cards — cardsLayout() via <DataGridView>
  • Kanban — kanbanLayout() grouped by status
  • MediaGrid — mediaGridLayout() with avatar thumbs

4. Toolbar (toggles — multi pick)

Each toolbar widget is independently togglable so you can see what disappears when:

  • <DataGridSearch>
  • <DataGridFilterBar>
  • <DataGridSort>
  • <DataGridColumnVisibility>
  • <DataGridDensityToggle>
  • <DataGridBulkActions>
  • <DataGridSelectionIndicator>
  • <DataGridGroupBy>
  • <DataGridExportButton>
  • <DataGridSearchColumns>
  • <DataGridPageSizeSelect> — standalone page-size dropdown (mode-agnostic)
  • <DataGridPaginationStatus> — mode-aware status readout

5. Overlay primitives (toggles)

Sit on top of any pagination mode:

  • Date-bucket separators — drops a virtual defineDateBucketColumn into the column array + mounts <DataGridDateBucketActivator>. Groups rows by their joined day so you see Slack-style "Today / Yesterday / Mar 14" section headers. Works in every layout via the existing groupBy infra.
  • <DataGridLiveTail> — wraps the grid in a fixed-height scroll container + mounts the live-tail primitive. Sticky "N new ↓" pill appears when paused; click to resume + scroll to bottom. Watches useDataGrid().rows.length for new arrivals.
  • Streaming (adapter.push) — fires setInterval that calls adapter.push(syntheticUser) every 1.5s. Real adapters open their push channel (WebSocket / SSE / poll) in subscribe(); the in-memory reference adapter exposes push() so demos like this can drive realtime without a fake socket. Combine with Live Tail to see auto-scroll-vs-pause behavior.

6. Behaviors (toggles)

Renderer-level flags:

  • Row selection
  • Row reorder (drag rows) — when on, a sub-radio appears with two options: Whole row / card (pointerdown anywhere lifts) or Icon only (≡) (only the auto-grip drags; row body stays clickable). See the Row reorder doc for the full mode + handle-placement story.
  • Inline-edit column (adds a column with meta.edit)
  • Sticky header
  • Column resize
  • Column reorder

7. Tuning (dropdowns)

  • Page size: 10 / 20 / 50 / 100 / 200
  • Adapter latency: Instant / 100ms / 300ms / 800ms (simulates a real network)

Implementation note — key to force resets

When paginationMode changes, cursor state from the previous mode would otherwise stay live and produce empty pages. The playground uses React's key prop on the providers to remount on mode change:

<DataGridProvider
  adapter={adapter}
  paginationMode={cfg.paginationMode}
  key={`provider-${cfg.paginationMode}-${cfg.latencyMs}`}
>

Real apps don't usually flip mode at runtime — this is a playground-specific gymnastics. Sample code in your own routes can drop the key.

Reading the source

The playground is one file: src/routes/kits.datagrid.playground.tsx — ~430 lines. Mostly:

  • PlaygroundConfig type — one giant state shape
  • ControlPanel component — radios + toggles + dropdowns wired to setCfg
  • GridBody component — conditional renders driven by cfg

It's intentionally a single file so you can grep it as a reference cookbook ("how do I conditionally mount <DataGridGroupBy>?" → look at the toolbar block). For your own apps you'd factor into pieces.
