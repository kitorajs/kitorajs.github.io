Pagination

The kit ships three pagination modes and eight UI primitives that map to the patterns real products use — cursor prev/next (Linear, GitHub), cursor infinite (Twitter, Bluesky), numbered offset (WordPress admin), or your own custom UI built on the same unified hook. Pick a mode at the provider, pick a UI primitive (or write one) at the body.

Architecture in 60 seconds

Three layers, three swap points:

  1. <DataGridProvider paginationMode="..."> picks the mode. Adapter contract changes shape (cursor vs offset query params), provider tracks the relevant state.
  2. useDataGridPagination() — a discriminated-union hook that exposes mode-appropriate state + actions. Every UI primitive reads from this hook. Build your own in 20 lines.
  3. UI primitives — drop-in components. Mount one (or none, or several). Replace any of them with custom UI without touching the data layer.
<DataGridProvider adapter={adapter} paginationMode="numbered">
  <DataGrid columns={cols} />
  <DataGridNumberedPagination />   {/* default UI — swappable */}
</DataGridProvider>

That's it. The renderer (table / virt / cards / kanban / media-grid) doesn't know which mode is on — it just reads rows from the provider.

The three modes

paged (default) — cursor prev/next

Linear / GitHub shape. The adapter accepts { first, after } (forward) or { last, before } (backward). The provider tracks one cursor + direction at a time; each step replaces the rows array.

Data shape:

adapter.load({ first: 20, after: 'user_482' })
// → { rows, pageInfo: { hasNextPage, endCursor, hasPreviousPage, startCursor } }

Default UI: <DataGridPagination> — Prev / Next / page-size / "1-20 of 213" range readout.

When to use: stable enterprise-style "click next" UX. Resilient to inserts/deletes in the underlying data (no offset drift). Cannot answer "jump to page 17".

infinite — cursor append (bidirectional)

Twitter / Bluesky / Instagram feed shape. Same cursor adapter contract as paged, but the provider tracks two cursors independently (topCursor + bottomCursor) and appends/prepends pages into a single growing rows array.

<DataGridProvider adapter={adapter} paginationMode="infinite">
  <DataGridInfiniteAnchor direction="up" />   {/* (optional) deep-link prepends */}
  <DataGrid columns={cols} />
  <DataGridInfiniteAnchor direction="down" /> {/* appends as user scrolls */}
</DataGridProvider>

See the dedicated Infinite scroll doc for the full mental model, the windowing-vs-infinite comparison, and the 500k-row combo example.

numbered — offset / limit

Classic admin-table shape. WordPress admin / SQL-tool / per-DB-row-management UIs. The adapter accepts { offset, limit } and the provider derives offset from the current page number. Supports jump-to-page-N because pages are addressable.

Data shape:

adapter.load({ offset: 320, limit: 20 })
// → { rows, totalCount: 530, pageInfo: { … } /* still emitted but ignored */ }

Default UI: <DataGridNumberedPagination> (ellipsis: 1 2 3 … 17 18 19 [Next]) often paired with <DataGridFirstLastButtons> + <DataGridJumpToPage>.

When to use: admin tables, jump-to-page-N matters, total page count visible. Trade-off: offset drifts under concurrent inserts/deletes (rows shift). For stable mid-feed deep-linking use paged or infinite instead.

Adapter contract — additive, non-breaking

DataGridQuery now has optional offset + limit alongside the existing cursor fields. Adapters declare which shapes they accept:

const adapter: DataGridAdapter<User> = {
  load: (q) => fetch(...),
  pagination: { cursor: true, offset: true },  // ← declare here
}

Defaults when omitted: { cursor: true, offset: false } — every pre-existing adapter keeps working without changes.

inspectCapabilities(adapter) returns { cursorPagination, offsetPagination, … }. The provider raises a named error at mount time if paginationMode doesn't match what the adapter supports — no silent "rows never load" bugs:

[DataGridProvider] paginationMode="numbered" requires the adapter to declare
`pagination: { offset: true }`. The current adapter only supports cursor
pagination (first/after/last/before). Either switch to paginationMode="paged" /
"infinite", or add offset/limit support to the adapter's load() method and set
pagination.offset to true.

The unified hook — useDataGridPagination()

One hook abstracts every mode. Branch type-safely on .mode:

const p = useDataGridPagination()

if (p.mode === 'paged') {
  p.goNext()
  // p.hasNext / p.hasPrev / p.pageInfo / p.totalCount
}
if (p.mode === 'infinite') {
  p.loadMore('down')
  // p.hasMore / p.loadingMore
}
if (p.mode === 'numbered') {
  p.goPage(7)
  // p.page / p.totalPages / p.goFirst / p.goLast / p.goPrev / p.goNext
}

Why this matters: every default UI primitive in the kit is a thin wrapper over this hook (40-90 lines each). Replace any of them with your own UI without re-implementing the state machine.

Example — a fully custom numbered paginator in 25 lines:

function MinimalNumberedPagination() {
  const p = useDataGridPagination()
  if (p.mode !== 'numbered') return null
  return (
    <div className="flex gap-1">
      <button disabled={!p.hasPrev} onClick={p.goPrev}>‹</button>
      {Array.from({ length: p.totalPages }, (_, i) => i + 1).map((n) => (
        <button
          key={n}
          onClick={() => p.goPage(n)}
          aria-current={n === p.page ? 'page' : undefined}
          style={{ fontWeight: n === p.page ? 'bold' : 'normal' }}
        >
          {n}
        </button>
      ))}
      <button disabled={!p.hasNext} onClick={p.goNext}>›</button>
    </div>
  )
}

Recipes

Numbered with all the trimmings

<DataGridProvider adapter={adapter} paginationMode="numbered">
  <DataGrid columns={cols} />

  <div className="flex items-center justify-between">
    <div className="flex items-center gap-2">
      <DataGridFirstLastButtons show="first" />
      <DataGridNumberedPagination />
      <DataGridFirstLastButtons show="last" />
    </div>
    <DataGridJumpToPage />
  </div>
</DataGridProvider>

Live at /kits/datagrid/numbered.

Manual "Load more" infinite

When auto-scroll fetching is undesired (slow networks, "I want explicit control" users):

<DataGridProvider adapter={adapter} paginationMode="infinite">
  <DataGrid columns={cols} />
  <DataGridLoadMoreButton direction="down" />   {/* instead of <DataGridInfiniteAnchor> */}
</DataGridProvider>

Cursor pagination + show "page 3 of 27"

paged mode tracks one cursor at a time; it does not know the current page number. If you want a "page N of M" readout, either:

  • Adapter returns totalCount and you compute pages locally based on pageSize
  • Or switch to numbered mode (built-in page / totalPages)

Capability-driven UI

For tools that ship multiple modes and let users pick at runtime, read both adapter capabilities and pick a default:

const caps = inspectCapabilities(adapter)
const defaultMode =
  caps.offsetPagination && !caps.cursorPagination ? 'numbered'
  : caps.cursorPagination ? 'paged'
  : 'paged'  // will throw at mount; surface a better error first

The playground demonstrates this dynamic — flipping paginationMode in real time without remounting the data layer.

Overlay primitives — work on top of any mode

Two primitives don't pick a mode — they sit on top of whichever mode you've chosen and add a behavior. Both work in paged, infinite, and numbered modes without conditionals.

Date-bucket separators — Slack / Discord shape

Render inline section headers between rows that fall into different "buckets" (typically calendar days). Shipped as two pieces:

  • defineDateBucketColumn<TRow>({ bucketKey, format }) — a column factory. The returned column has no body cell; it carries meta.groupValue (your bucket key extractor) + meta.groupLabel (your formatter) that the existing groupBy infra renders as section headers.
  • <DataGridDateBucketActivator /> — an imperative activator. Mount it inside the provider tree to set groupByColumnId to the bucket column on mount, restore on unmount. Skip it if you want manual control via <DataGridGroupBy> or defaultGroupByColumnId.
import {
  defineDateBucketColumn,
  formatRelativeDay,
  startOfDayKey,
  DataGridDateBucketActivator,
} from '@kitora/datagrid'

const dateBucket = defineDateBucketColumn<LogRow>({
  bucketKey: (r) => startOfDayKey(new Date(r.createdAt)),
  format: (key) => formatRelativeDay(new Date(key)),  // "Today" / "Yesterday" / "Mar 14"
})

const columns = defineColumns<LogRow>()([dateBucket, ...regularCols])

<DataGridUIProvider defaultGroupByColumnId="date-bucket">
  <DataGridProvider adapter={adapter}>
    <DataGrid columns={columns} />
    <DataGridDateBucketActivator />   {/* optional — enforces the grouping */}
  </DataGridProvider>
</DataGridUIProvider>

The exported helpers startOfDayKey(date) + formatRelativeDay(date, now?) cover the common Slack-style label set. For custom buckets (per-month, per-hour, by-user), pass your own functions to bucketKey + format.

Why piggy-back on groupBy instead of a custom render path? Because the same primitive then automatically works in cards / kanban / media-grid layouts that already read groupByColumnId. Zero per-layout duplication.

<DataGridLiveTail> — auto-scroll to newest

For tail -f / Datadog Logs / Slack-newest-message shape — sticky "N new ↓" badge appears when new rows arrived but the user has scrolled away, click to catch up.

function LogStream() {
  const scrollRef = useRef<HTMLDivElement | null>(null)
  return (
    <div className="relative">
      <div ref={scrollRef} className="max-h-[520px] overflow-y-auto">
        <DataGrid columns={cols} />
      </div>
      <DataGridLiveTail
        scrollContainerRef={scrollRef}
        pauseWhen={['hover', 'manualScroll']}
        stickThreshold={64}
      />
    </div>
  )
}

State machine: following ⇄ paused. While following, new rows trigger an auto-scroll to bottom. Pointer hover or manual scroll-up flips to paused; the badge counts new arrivals since pause. Click → resume + jump to bottom. Configurable pauseWhen (subset of 'hover' and 'manualScroll') lets you disable a transition source — useful for kiosk-mode log viewers that should never pause.

Pairs naturally with adapter.subscribe (see below). Without subscribe, it still fires on row-count deltas from loadMore, manual refresh(), or any other source that grows the rows array.

adapter.subscribe — realtime push channel

Optional adapter method that opens a server-pushed event stream. The provider wires it on mount:

adapter.subscribe?({
  onUpsert: (row) => { /* row id matches an existing row → replace; else append */ },
  onRemove: (rowId) => { /* drop from rows */ },
}) => () => void  // unsubscribe — called on unmount + adapter swap

Capability-detected via inspectCapabilities(adapter).subscribe. Implementations:

  • WebSocket / SSE — open the connection in subscribe(), return a closer.
  • Polling — setInterval that fetches deltas + invokes the handlers; clear on return.
  • Demo / test — the reference createInMemoryAdapter exposes push(row) + remove(rowId) methods. Calling them fans events out to every subscriber; the /kits/datagrid/log-stream demo wires a 1.5s interval that pushes synthetic log rows.
const adapter = createInMemoryAdapter<LogRow>({ initial: rows })

// Later, from anywhere:
setInterval(() => adapter.push(makeLogRow()), 1500)
