Adapter contract

The datagrid is fully headless. It never knows your transport (REST, GraphQL, Prisma, Supabase, whatever) — it only calls your adapter. Implement DataGridAdapter<TRow, TWhere> to bridge it.

Shape

interface DataGridAdapter<TRow, TWhere = unknown> {
  /** Mandatory — fetch a page given the live query. */
  load(query: DataGridQuery<TWhere>): MaybePromise<DataGridResult<TRow>>

  /** Per-row mutators — each one is optional. */
  updateRow?(id: string, patch: Partial<TRow>): MaybePromise<TRow>
  deleteRow?(id: string): MaybePromise<void>
  duplicateRow?(id: string): MaybePromise<TRow>

  /** Bulk mutators. */
  bulkUpdate?(ids: string[], patch: Partial<TRow>): MaybePromise<void>
  bulkDelete?(ids: string[]): MaybePromise<void>

  /** Row reorder. */
  moveRow?(rowId: string, beforeRowId: string | null): MaybePromise<void>
  bulkMoveRows?(rowIds: string[], beforeRowId: string | null): MaybePromise<void>

  /** Optional realtime push from your transport. */
  subscribe?(callbacks: SubscribeCallbacks<TRow>): () => void

  /** Optional declarative config. */
  filterFields?: FilterFieldDef[]
  sortOptions?: SortOption[]
  search?: SearchConfig<TWhere>
}

DataGridQuery is what the grid hands you on every load:

interface DataGridQuery<TWhere> {
  search: string
  filters: FilterCondition[]
  where?: TWhere               // resolved via filterFields + search.toWhere
  sort: SortRule[]
  first?: number               // page size
  after?: string | null        // cursor
  direction: 'forward' | 'backward'
}

And DataGridResult is what you return:

interface DataGridResult<TRow> {
  rows: TRow[]
  pageInfo: {
    endCursor: string | null
    startCursor: string | null
    hasNextPage: boolean
    hasPreviousPage: boolean
  }
  totalCount?: number          // optional; drives "1-20 of 1,234"
}

In-memory reference adapter

Use it for prototyping or as a pattern for your real adapter.

import { createInMemoryAdapter } from '@kitora/datagrid'

const adapter = createInMemoryAdapter<User>({
  initial: seedUsers,
  searchKeys: ['name', 'email', 'team'],
  /* optional configs */
  sortOptions,
  filterFields,
  search: { placeholder: 'Search users…', toWhere: (q) => ({ _q: q }) },
  latencyMs: 250,              // simulate a real network
})

Built-in support for: search-by-keys, sort, filter (via buildWhere), cursor pagination, updateRow / deleteRow / duplicateRow / bulkUpdate / bulkDelete / moveRow / bulkMoveRows. Mutators run locally on the in-memory array.

REST recipe

const restAdapter: DataGridAdapter<User> = {
  load: async (q) => {
    const params = new URLSearchParams({
      q: q.search,
      sort: q.sort.map((s) => `${s.fieldId}:${s.direction}`).join(','),
      first: String(q.first ?? 20),
      after: q.after ?? '',
    })
    const res = await fetch(`/api/users?${params}`)
    return res.json() as Promise<DataGridResult<User>>
  },
  updateRow: async (id, patch) => {
    const res = await fetch(`/api/users/${id}`, {
      method: 'PATCH',
      body: JSON.stringify(patch),
    })
    return res.json()
  },
  bulkDelete: async (ids) => {
    await fetch('/api/users/bulk-delete', {
      method: 'POST',
      body: JSON.stringify({ ids }),
    })
  },
}

Pagination is cursor-based — pageInfo.endCursor / pageInfo.startCursor are the boundaries of the current page. Real APIs (Linear, GitHub GraphQL) follow this shape natively.

GraphQL recipe

const gqlAdapter: DataGridAdapter<User, UserWhere> = {
  load: async ({ where, sort, first, after }) => {
    const { users } = await client.request(USERS_QUERY, { where, sort, first, after })
    return {
      rows: users.edges.map((e) => e.node),
      pageInfo: users.pageInfo,
      totalCount: users.totalCount,
    }
  },
}

Realtime

Implement subscribe to push updates from a WebSocket / SSE / Yjs without re-fetching:

subscribe: ({ onUpsert, onRemove }) => {
  const socket = openWS('/users')
  socket.on('user.upsert', onUpsert)
  socket.on('user.remove', (id) => onRemove(id))
  return () => socket.close()
}

Returned cleanup is called on unmount.

Capability inspection

inspectCapabilities(adapter) returns a boolean map of every optional method. The grid uses this internally to hide UI for missing mutators, but you can read it too:

import { inspectCapabilities } from '@kitora/datagrid'

const caps = inspectCapabilities(adapter)
// { updateRow: true, deleteRow: false, bulkDelete: false, … }

Useful for branching your own toolbar / shortcuts.

Imperative API via useDataGrid()

Inside any component below <DataGridProvider>:

const { rows, mutators, capabilities, totalCount, refresh, refetch } =
  useDataGrid<User>()

mutators.updateRow?.('u-1', { team: 'Platform' })
mutators.bulkDelete?.(['u-1', 'u-2'])
refresh()                                       // re-run load with current query

Optimistic updates: mutators.updateRow applies locally first, then calls the adapter; rollback happens automatically on rejection.
