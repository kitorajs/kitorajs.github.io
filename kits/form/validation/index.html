Validation

Rules on the field: built-in validators, a cross-field matches, two-axis timing, a named async validator from the registry, and a non-blocking warn channel. No hand-rolled schema and no effects; a whole-value Standard Schema (Zod/Valibot/JSON Schema) still plugs in through schema when you want one.

  • Required + cross-field
  • Validation timing modes
  • Async availability check
  • Rule library (pattern + range)
  • Warnings (non-blocking, V9)
  • Schemas that stop at the first issue
  • Suffix by validity

01Required + cross-field

Field rules plus a confirm-password rule; ErrorSummary aggregates them and Form.Submit gates on validity.Built frominputpassword-inputFieldShell · formReadOnlyValue · formTextChrome · formUsed inaffixalert-dialogapi-key-cardattachmentcomboboxdialogfilter-barfloat-button

Min 8 characters

02Validation timing modes

The same email rule under validateOn blur vs change vs submit — feel the difference.Built frominputFieldShell · formReadOnlyValue · formTextChrome · formUsed inaffixalert-dialogapi-key-cardattachmentcomboboxdialogfilter-barfloat-button

validateOn=blur

Surfaces when you leave the field — the default; no nagging while typing.

validateOn=change

Validates on every keystroke — eager, good for live-availability hints.

validateOn=submit

Holds all errors until submit — least interruptive.

03Async availability check

A named async validator with debounce and abort — stale responses are dropped, last keystroke wins.Built frominputFieldShell · formReadOnlyValue · formTextChrome · formUsed inaffixalert-dialogapi-key-cardattachmentcomboboxdialogfilter-barfloat-button

Try 'ada' or 'admin' (taken) vs anything else

Each keystroke schedules a debounced async check; a newer run aborts the older one so the last keystroke always wins. The field shows its validating state while in flight.

04Rule library (pattern + range)

Pattern (URL) and numeric-range rules; errors surface on blur and clear on the next keystroke once fixed.Built frominputFieldShell · formNumberInput · pickersReadOnlyValue · formTextChrome · formUsed inaffixalert-dialogapi-key-cardattachmentcomboboxdialogfilter-barfloat-button

05Warnings (non-blocking, V9)

A parallel advisory channel — amber, not red. Submit/validate/focus-first-error all ignore warnings.Built frompassword-inputFieldShell · formReadOnlyValue · formTextChrome · formUsed inaffixalert-dialogapi-key-cardattachmentcomboboxdialogfilter-barfloat-button

Type 1–9 chars to see an advisory (amber, not red)

06Schemas that stop at the first issue

Valibot with abortEarly, Yup and many custom vendors report one failing field per run. Silence about the others is not proof they are valid, so their errors are kept until a probe run shows them fixed.Built frominputFieldShell · formReadOnlyValue · formTextChrome · formUsed inAddressField · formAutoForm · formBuilderRoot · form-builderCheckboxGroupField · formFieldPreview · form-builderFormDialog · formFormSheet · formPhoneField · form

Trusting silence (schemaReports: "all")

Clear the name: the vendor stops there, and the email error vanishes although the email is still wrong.

Default (auto → first for this vendor)
