Migrating from React Hook Form

Moving a React Hook Form form to the engine: how the two models differ, the API mapping, and the six most common React Hook Form shapes rewritten. Under each example is the React Hook Form "before" (plain React Hook Form, not compiled here); every "after" is type-checked and running.

How the two models differ

  • Fields, not inputs. React Hook Form registers native inputs and leaves labels, errors and ARIA to you. Here a field is a component bound by name that renders its label, control, error, description and accessibility wiring, and posts its value under its path in a native form.
  • Rules live in a model. required, rules, visibleIf, derived values and array bounds are recorded in one serializable definition, whether you write JSX or defineForm. The same definition validates on a server (validateValues) and renders with AutoForm.
  • Per-path subscriptions. Each field subscribes to its own path, so typing in one field re-renders only that field. useFormValue subscribes to one path instead of re-rendering the whole form like watch().
  • Every write has an origin. user, external or programmatic. A controlled form (value + onChange) only reports user edits, which removes the echo loops React Hook Form needs workarounds for.

Rules move from a resolver onto the fields. They are recorded in a serializable model, so the same checks can run on a server (validateValues). Each field renders its own label, error, aria-invalid and description wiring; ErrorSummary replaces mapping formState.errors by hand; Form.Submit disables itself while submitting. A whole-value Standard Schema (Zod, Valibot, ArkType) still plugs in through useForm({ schema }) when you want to keep one.

The array is a row template with row-relative names (.item); rows keep stable ids through moves, so errors and focus follow the row. min/max gate Add/Remove with a spoken reason instead of a silently disabled button. A computed total is a derived value in the model, so there is no useWatch + useEffect + setValue loop and the server recomputes it.

Before (React Hook Form, not compiled here)
import { useFieldArray, useForm, useWatch } from "react-hook-form" export function InvoiceForm() {  const { control, register, handleSubmit, setValue } = useForm<Invoice>({ defaultValues: { lines: [{ item: "", qty: 1, price: 0 }], total: 0 } })  const { fields, append, remove, move } = useFieldArray({ control, name: "lines", rules: { minLength: 1 } })  const lines = useWatch({ control, name: "lines" })  useEffect(() => {    setValue("total", lines.reduce((sum, l) => sum + l.qty * l.price, 0))  }, [lines, setValue])  return (    <form onSubmit={handleSubmit(api.save)}>      {fields.map((field, index) => (        <div key={field.id}>          <input {...register(`lines.${index}.item`, { required: true })} />          <input type="number" {...register(`lines.${index}.qty`, { valueAsNumber: true })} />          <input type="number" {...register(`lines.${index}.price`, { valueAsNumber: true })} />          <button type="button" onClick={() => move(index, index - 1)} disabled={index === 0}>Up</button>          <button type="button" onClick={() => remove(index)} disabled={fields.length === 1}>Remove</button>        </div>      ))}      <button type="button" onClick={() => append({ item: "", qty: 1, price: 0 })}>Add line</button>      <output>{useWatch({ control, name: "total" })}</output>      <button>Save invoice</button>    </form>  )}

04watch, setValue and shouldUnregister

Conditional fields are a When in the model: hidden values leave the payload. useFormValue subscribes to one path; setValue keeps its name.Built fromcheckboxinputFieldShell · formReadOnlyValue · formTextChrome · formUsed inaffixalert-dialogapi-key-cardattachmentcomboboxdialogfilter-barfloat-button

Live payloadclean · idle
{
  "email": "",
  "company": false
}

A conditional block is a When recorded in the model: hidden fields stop validating and leave the payload (whenHidden), so shouldUnregister is not needed. useFormValue(form, path) subscribes to one path and re-renders only the component that reads it (watch re-renders the whole form). form.setValue(path, value) keeps its name; every write is tagged with an origin.

Before (React Hook Form, not compiled here)
import { useForm } from "react-hook-form" export function BillingForm() {  const { register, handleSubmit, watch, setValue } = useForm<Billing>({ defaultValues: { email: "", company: false }, shouldUnregister: true })  const company = watch("company") // re-renders the whole form on every change of "company"  return (    <form onSubmit={handleSubmit(console.log)}>      <input type="email" {...register("email", { required: true })} />      <input type="checkbox" {...register("company")} />      {company && (        <>          <input {...register("companyName", { required: true })} />          <input {...register("vat")} />        </>      )}      <button type="button" onClick={() => setValue("company", !company)}>Toggle company</button>      <button>Continue</button>    </form>  )}

Submit as admin to see it. trigger(name) is validate(name).Built frominputFieldShell · formReadOnlyValue · formTextChrome · formUsed inaffixalert-dialogapi-key-cardattachmentcomboboxdialogfilter-barfloat-button

  "username": "",
  "email": ""

Throw a SubmitError with fields from the submit handler (or return one from a server action): each message lands on its field, the first errored field gets focus, and editing a field clears its server message. Form.Status shows the form-level message. trigger(name) is form.validate(name). submitErrorFromResponse(res) turns a fetch Response (422, 409, 429, 403) into the right SubmitError.

Before (React Hook Form, not compiled here)
import { useForm } from "react-hook-form" export function AccountForm() {  const { register, handleSubmit, setError, trigger, formState: { errors } } = useForm<Account>()  const onSubmit = async (values: Account) => {    const res = await fetch("/accounts", { method: "POST", body: JSON.stringify(values) })    if (res.status === 422) {      const body = await res.json()      for (const [name, message] of Object.entries(body.fields)) setError(name as keyof Account, { message: String(message) })      setError("root.server", { message: "Please fix the highlighted fields" })    }  }  return (    <form onSubmit={handleSubmit(onSubmit)}>      <input {...register("username", { required: true })} />      {errors.username && <p role="alert">{errors.username.message}</p>}      <input type="email" {...register("email", { required: true })} />      {errors.root?.server && <p role="alert">{errors.root.server.message}</p>}      <button>Create account</button>      <button type="button" onClick={() => trigger("email")}>Check email</button>    </form>  )}

An accordion form embedded in an editor node that owns the data. Controlled mode replaces the useWatch → reset loop, the disableWatch flag, the JSON.stringify echo check and the focus-restore timer.Built frominputtextareaFieldShell · formReadOnlyValue · formReorderHandle · formTextChrome · formUsed inAddressField · formAutoForm · formBuilderRoot · form-builderCheckboxGroupField · formFieldPreview · form-builderFormDialog · formFormSheet · formPhoneField · form

An accordion of FAQ / step items, each with a nested image, embedded in a Lexical node that owns the data and the undo history. In React Hook Form it looped: useWatch wrote to the node, the node re-rendered the form with a new defaultValue, reset() fired useWatch again. The shipped fix was three workarounds: a disableWatch flag, a JSON.stringify echo comparison, and a keydown timer to restore the focus that reset() stole. Controlled mode (useForm({ value, onChange })) removes all three: host writes apply with origin external and never reach onChange, only user edits do; an external value patches only the paths that changed, so the field being typed in keeps focus; undo is the host writing an older value. The same pattern runs on /kits/form/embedded.

Before (React Hook Form, not compiled here)
// an accordion form inside a rich-text editor node (shape, simplified)export function AccForm({ defaultValue, onDataChange }: Props) {  const { control, register, reset, getValues } = useForm<Accordion>({ defaultValues: defaultValue })  const { fields, append, remove } = useFieldArray({ control, name: "items" })  const data = useWatch({ control })  const disableWatch = useRef(false)   // form → editor: every change is written to the Lexical node (debounced)  useEffect(() => {    if (disableWatch.current) return    const t = setTimeout(() => onDataChange(data), 300)    return () => clearTimeout(t)  }, [data])   // editor → form: the node re-renders us with a new defaultValue (our own echo, or undo)  useEffect(() => {    // hack 1: JSON.stringify echo check — skip our own write coming back    if (JSON.stringify(defaultValue) === JSON.stringify(data) && JSON.stringify(defaultValue) === JSON.stringify(getValues())) return    // hack 2: silence the watcher while reset() replays the value    disableWatch.current = true    reset(defaultValue) // re-renders every field and steals focus    disableWatch.current = false  }, [defaultValue])   // hack 3: put focus back after reset() (https://github.com/react-hook-form/react-hook-form/issues/3719)  const onKeyDown = (e: KeyboardEvent) => setTimeout(() => (e.target as HTMLElement).focus(), 0)  // …fields.map with register(`items.${i}.title`), a type select, image src/alt inputs…}

Migrating a codebase

  • Move one form at a time; both libraries can live in one app. Start with forms that have the most hand-written error and ARIA markup, since that code disappears.
  • Keep your Zod (or Valibot, ArkType) schema at first by passing it as schema; move rules onto fields later where you want them on the server through the model, or in an AutoForm.
  • If a schema stops at the first issue (Valibot with abortEarly, Yup), set schemaReports: "first" so silence about a field is not taken as "valid". See the "Schemas that stop at the first issue" example on /kits/form/validation.
  • Replace useEffect + setValue chains with derived values and When / Variant blocks; replace shouldUnregister with whenHidden.
  • Replace hand-mapped 422 handling with submitErrorFromResponse(res) or throw new SubmitError({ fields }).
  • A codemod for the mechanical part (register → field components, useFieldArray → FieldArray) is not built.
