Adapter & persistence

Tabster owns the layout shape. Storage is yours.

The contract

interface TabsterAdapter {
  load(): MaybePromise<TabsterSnapshot | null>
  save(snapshot: TabsterSnapshot): MaybePromise<void>
  clear?(): MaybePromise<void>
}

interface TabsterSnapshot {
  version: number
  layout: SerializedLayout
  meta?: Record<string, unknown>
}

Implement once; wire it via the adapter prop. Tabster handles loading on boot, saving on every layout change (toggleable via autoPersist), and routing it through your enterEditMode → save / discard flow.

Reference implementations

localStorage

import { Tabster, createLocalStorageAdapter } from '@kitora/tabster'

const adapter = createLocalStorageAdapter({ key: 'my-app:dock' })

<Tabster panels={PANELS} initialPanels={INITIAL} adapter={adapter} />
  • Auto-prefixes the key with tabster: if you didn't.
  • SSR-safe — load returns null when window is undefined.
  • Catches quota / private-mode errors and routes them to onError.

In-memory

For tests, Storybook, or "I'll wire my own persistence later":

import { createInMemoryAdapter } from '@kitora/tabster'
const adapter = createInMemoryAdapter()

The returned object also exposes peek() so tests can read state without going through the contract.

Server-backed (your own)

function createRemoteAdapter(userId: string): TabsterAdapter {
  return {
    load: async () => {
      const res = await fetch(`/api/users/${userId}/layout`)
      return res.ok ? await res.json() : null
    },
    save: async (snapshot) => {
      await fetch(`/api/users/${userId}/layout`, {
        method: 'PUT',
        body: JSON.stringify(snapshot),
      })
    },
    clear: async () => {
      await fetch(`/api/users/${userId}/layout`, { method: 'DELETE' })
    },
  }
}

Throwing or rejecting is fine — Tabster catches and logs, then falls back to initialPanels for load, and to a console warning for save. No restore call ever crashes the dock.

Versioned snapshots + migrators

Bump version when the layout shape changes in a breaking way. Register a migrator for each from → from + 1 step:

const SCHEMA_VERSION = 3

const MIGRATORS: TabsterMigratorMap = {
  1: (snap) => ({ ...snap, version: 2, layout: renameOldComponents(snap.layout) }),
  2: (snap) => ({ ...snap, version: 3, layout: addDefaults(snap.layout) }),
}

<Tabster
  panels={PANELS}
  initialPanels={INITIAL}
  adapter={adapter}
  version={SCHEMA_VERSION}
  migrators={MIGRATORS}
/>
  • Migrators chain automatically from the stored version to the current.
  • If any migrator is missing or returns null, Tabster discards the snapshot and falls back to initialPanels. The dock never enters a broken state.
  • Newer-than-current snapshots are also rejected (downgrade not supported by default).

Layouts saved before the move to @kitora/dock

Tabster used to run on dockview, so a user's adapter may still hold a dockview layout inside its snapshot. Nothing to do: Tabster passes every loaded layout (adapter snapshots, initialLayout, loadLayout, restore) through DOCKVIEW_MIGRATOR, which converts dockview's grid, floating groups and popout groups (popouts come back as in-page floats) into the dock's schema, and the next save writes the new shape under the same key. Your own migrators (the snapshot version chain above) run first and are unchanged. To convert a stored layout yourself, for example in a server-side backfill:

import { isDockviewLayout, migrateDockviewLayout } from '@kitora/tabster'

if (isDockviewLayout(snapshot.layout)) snapshot.layout = migrateDockviewLayout(snapshot.layout)

Edit mode (draft / committed split)

Adapters auto-persist on every layout change by default. Turn it off when you want explicit Save / Discard semantics:

const apiRef = useRef<TabsterApi | null>(null)

<Tabster
  adapter={adapter}
  autoPersist={false}      // optional — implied by entering edit mode
  onReady={({ api }) => (apiRef.current = api)}
/>

// later, in a button:
apiRef.current?.enterEditMode()   // snapshot current state
apiRef.current?.saveEditMode()    // commit + persist
apiRef.current?.discardEditMode() // rollback to snapshot

enterEditMode pauses auto-persist; the user can rearrange freely. saveEditMode flushes to the adapter. discardEditMode restores the pre-edit snapshot via fromJSON().

Imperative escape hatches

api.snapshot()                  // → { version, layout }
api.restore(snapshot)           // applies a snapshot
api.persist()                   // force-save through the adapter
api.reload()                    // re-read adapter + restore
api.isEditing()                 // boolean
